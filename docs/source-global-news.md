# Global news and official scheduled events

## Product scope

The hosted `/news` workspace is a small, attributable **official-source feed reader and release-calendar view**, integrated with FinanceFlowAtlas navigation. It is not comprehensive global journalism. Its initial coverage is three selected US/UK government publishers in technology, geopolitics and finance, plus the US Bureau of Labor Statistics (BLS) release calendar. A government statement remains that government's statement, not independently verified reporting. English source titles/excerpts remain in their original language inside a Chinese interface; no unverified AI translation, forecast, sentiment score, price-effect claim or fabricated event is generated.

The public-source acquisition endpoint is `/api/news`. Existing site authentication is unchanged. No API keys, paid subscription, new database migration, scheduled job or alert service is required or installed. Opening/refetching the page can acquire sources. Closing it stops the page's requests. The application does not promise unattended monitoring or timely delivery of breaking news.

## Date and evidence semantics

- News `publishedAt` is a source publication timestamp, or a source update timestamp when `publicationTimeKind` is `updated`. An Atom `<updated>` field is never labelled as original publication. Missing or floating timestamps stay unknown. A source date without time remains `publishedDate`, not an invented midnight instant. `occurredAt` is always null: publication is not evidence of event occurrence.
- `fetchedAt` is successful acquisition time, `lastAttemptAt` is request attempt time and `generatedAt` is response assembly time. None is substituted for a source timestamp. `nextRefreshAt` is the earliest permitted next acquisition on a subsequent request, not a scheduled job or guaranteed delivery time.
- Calendar `DTSTART` supplies event time. `DTSTAMP` / `LAST-MODIFIED` are revision metadata and are not treated as publication. UTC timestamps and explicit IANA timezones are supported. BLS's actual `US-Eastern` identifier maps to `America/New_York` with DST rules. Ambiguous/nonexistent civil times, unknown zones and floating local times are skipped with a visible warning.
- Date-only events preserve dates and the exclusive ICS `DTEND` in `endDate`; they have no synthetic UTC instant. The view includes events **starting** in the next 90 days, not every currently ongoing multiday event. Date-only filtering uses the source timezone if known, otherwise UTC as a disclosed date-window convention. The UI displays known instants in `Asia/Shanghai`; this does not imply Shanghai was the source timezone.
- Cancelled/tentative future entries remain explicitly labelled. Same-source UID revisions select the greatest valid nonnegative integer `SEQUENCE`, then latest revision timestamp. Unsupported recurring/exception schedules are skipped and disclosed, never expanded into guessed events. This first adapter does not infer meetings from RSS publication dates or maintain a hard-coded future calendar.
- News are limited to the preceding 30 days when dated; unknown-date records remain labelled unknown. Future-dated news are omitted. Each source contributes at most 60 current-window items. An empty successful source is distinct from an unavailable source and does not prove that no real-world news/event exists.
- Deduplication uses normalized canonical news URLs, removing only fragments and known tracking parameters. Equal titles on different URLs are not merged and are not evidence of corroboration. Calendar identity and start are retained in addition to its URL, because BLS releases can share one schedule link. UID revision consolidation is not a claim of corroboration; the response dedup counters describe final URL/identity duplicate removal, not a count of source revisions.
- Category comes from the reviewed source. Region tags combine publisher geography with simple literal title matches. Related-market keys are topic/navigation context in the existing catalog (`fx`, `cftc`, `kraken`), not predictions, causal price/flow effects, complete geographic tagging or investment advice.

## Acquisition and failure behavior

`apps/site/lib/news/sources.ts` is a closed reviewed allowlist. Query parameters and feed-supplied links cannot select a fetch target. Only the four configured feed URLs are requested. Redirects are never followed. Article links must use HTTPS, contain no credentials or nondefault port and match an exact reviewed source host; no scripts or remote enclosures execute.

The service concurrently fetches the four feeds with an 8-second whole-request deadline (including streaming body), 1 MiB maximum decoded body per source, strict UTF-8 and bounded record/nesting counts. RSS/Atom uses the installed `saxes` parser, rejects DTDs/external entities and malformed XML, validates namespace/root structure, and emits inert plain text only. ICS parsing supports a deliberately limited non-recurring event subset, unfolds lines, validates dates/timezones and bounds lines/records. Nothing in a feed is executed or treated as an instruction.

The in-memory cache is **per Worker isolate**, coalesces same-isolate concurrent requests and has a 15-minute minimum interval. It is not durable, not shared across workers and not a global provider rate gate. The browser's five-minute checks/manual refresh do not bypass the server gate. Worker eviction/restart loses cached evidence and stopped-source state; a separately approved durable shared gate would be needed before making deployment-wide rate-limit or permanent-stop claims.

Transient network/format/5xx failures retain successful evidence for at most 24 hours with `stale` status, the original acquisition timestamp and the current error. Expired evidence is suppressed even during a long cooldown. HTTP 429/503 `Retry-After` is respected. Explicit 401/403/451, any redirect, or an HTML access challenge suppress prior rows and stop automatic retries **for that isolate**. Broken/hanging stream cancellation cannot convert a known denial into a transient retry. The implementation does not change identity, switch domains, proxy, solve challenges or retry through alternate routes.

The API returns 200 for successful/partial coverage and 503 with the same structured `NewsSnapshot` payload when all sources are unavailable. Every source reports status, warnings, acquisition and attempt times, next allowed attempt (null if halted), terms, attribution and visible item count. Responses use `Cache-Control: no-store`. A stale/partial response is never passed off as newly published evidence.

## Verification

- Runtime smoke on 2026-11-09: the actual Fed RSS, NIST RSS, FCDO Atom and BLS ICS endpoints returned HTTP 200 without redirects. Their original content types were XML/RSS, RSS, Atom and `text/calendar`. The complete `NewsService` parsed all four successfully, producing 28 news/official-update entries and 20 future BLS releases in that observed window. Those counts are a point-in-time check, not fixtures or coverage guarantees. The final FCDO news/communications URL was separately fetched and parsed successfully (20 entries, no warnings) before replacing the broader activity feed. No captured headlines/schedules are bundled or used as fallbacks.
- The web research reader's “unsupported content-type” result for raw RSS/Atom/ICS was not treated as runtime success. The HTTP/parse smoke above was a separate actual runtime check. Production Worker egress can differ; a local pass does not certify hosted deployment availability.
- Automated tests are synthetic and perform no external network requests. Run from `apps/site`: `npx vitest run --config vitest.config.ts tests/news-ingestion.test.ts tests/news-service.test.ts tests/news-route.test.ts`. They cover XML/ICS safety and dates, unknown timestamps, DST transitions, canonical-link dedup, UID revisions/cancellation, recurrence skipping, complete/partial/empty failure, bounded bodies/deadlines, coalescing, cache expiration, permission stops including cancellation failures, Retry-After and API status.
- Integration checks cover the Chinese UI, client contract, navigation, typecheck, production build and broader regressions separately. A repository change is not a production deployment.
