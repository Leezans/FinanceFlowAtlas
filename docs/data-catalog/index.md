# FinanceFlowAtlas 全球金融数据目录与实施路线

编制日期：2026-11-04。目标仓库：[Leezans/FinanceFlowAtlas](https://github.com/Leezans/FinanceFlowAtlas)。本交付是数据研究与接入设计，不是已完成的数据连接、代码实现或上线报告。本轮文档整合没有重跑 API 样本、付费订阅、许可申请或全量采集。项目已有 PIP F51 与 TIC 的真实采集和连接器证据，见第 3 节；这与其余来源仍处于研究阶段、以及尚未部署的状态严格区分。下文“本轮未验证”不能被解释为项目从未测试。

## 1. 阅读入口和范围

- [全球股市、机构交易与跨境证券](equities.md)：按全球基线、美洲、欧洲、亚洲、中东、非洲、大洋洲分类；国家/交易所统计与投资者分类；另外列出尚待核验的覆盖候选。
- [跨资产数据源与接入](cross-asset.md)：银行、宏观金融账户、基金/ETF、债券、期货、外汇、加密资产及商业数据选项。
- [数据类型与展示设计](display-design.md)：地图、排名、网络、下钻、刷新、缺失、口径和验收。

三个目录相互补充，重复机构并非额外覆盖。IMF、TIC、BIS 等在不同资产章节出现时应使用同一来源注册项；只有不同数据集或许可产品才建立独立适配器。目录不是全球完整普查：没有确认的经济体、市场、资产和时期必须保留为空白或候选，不得静默补齐。

**推荐产品承诺：**“跨市场、跨资产的资金交易、持仓与市场活动观察平台，逐项标明覆盖和时效。”目前证据不支持“全球所有资金实时流向”或“所有国家均可下钻至机构、行业和个股”。

## 2. 统一分类

### 2.1 指标主类型与质量必须正交

|主类型|典型子类型|可加总的基本约束|默认图形|
|---|---|---|---|
|`flow` 期间流量|证券净交易、购买、出售、净申赎、净发行、链间转移|同口径、同期间、同单位、互斥范围；不能跨统计体系相加|正负柱、历史曲线；有双边证据时才用流向图|
|`position` 时点存量|证券持仓、银行债权、未平仓合约、稳定币供应|同一时点和互斥范围；需明确合并规则|配置树图、排名、敞口矩阵|
|`activity` 交易活动|成交量、成交额、换手|去重规则一致，不能当作净流入|热力图、排名、时间序列|
|`price_return` 价格与收益|价格、回报、收益率、利差|通常不可直接加总；组合加权要有权重和方法|折线、回报热力图、小多图|

`observed / estimated / derived` 是方法标签，不是第五种资金类型；例如 EPFR 配置地区流量是 `flow + estimated`，BIS 调整后变化应保留官方近似流量的限定，链上转账即使实测也不等于投资交易。`provisional / revised` 是发布状态，不应与估算混为一谈。合约净多头增加不自动等于净现金投入。

### 2.2 三条独立分类轴

- **资产：**股票、基金份额/ETF、政府债、机构债、企业债、银行贷款与存款、外汇、金融衍生品、加密资产；直接投资/储备资产按宏观工具单独保留。商品现货、房地产、私募资产、保险及养老金微观持仓目前没有形成独立的已核验来源目录，属于范围缺口。
- **地域：**全球可比统计 → 报告经济体/对手经济体 → 市场；必须指定居民地、发行人地、基金注册地、国籍、托管地、销售台或交易所，不能统一压成一个 `country` 字段。
- **主体：**官方/私人、机构/个人、银行/基金/保险/养老金、境内/境外等均依来源定义。不同来源的“机构”不是天然同一人群。

“国家 → 行业 → 个股”不是统一数据树。宏观 BOP 的国家净交易不能分配给股票行业，更不能按市值分配到个股后称为实测流量。合法的视图切换必须显示新的来源和指标。

## 3. 证据阶段、责任与发布状态

### 3.1 不用一个“已验证”标签替代所有检查

|阶段|含义|必须保存的证据|本交付状态|
|---|---|---|---|
|C|研究候选|机构名、待解问题；不能虚构接口|股票目录候选队列|
|V1|官方产品/说明已发现|官方 URL、核查日期、相关限制|目录主体处于此阶段|
|V1-H|仅历史官方样例|样例时期、当前连续性未知|JSE、肯尼亚样例等|
|V2|端点/文件实测|实际请求或下载记录、响应状态、样本、元数据、时间|项目 PIP F51/TIC 已有实测；本轮未重跑，其余待测|
|V3|语义与质量验证|单位、符号、频率、缺失、对账、修订及覆盖报告|不能仅由成功摄取推定完整通过，需逐项核对|
|I1|适配器实现并通过测试|仓库路径、提交标识、测试结果、可重复命令|PIP F51/TIC 连接器已有提交；完整测试证据本轮未独立复核|
|I2|生产运行验证|部署版本、真实抓取记录、监控与恢复演练|尚未部署，不能称全面上线|

阶段不能跨级推定：网页打开不是 V2；API 返回 200 不是 V3；代码存在不是 I2。API 无法访问时可以评估官方文件路线，但不得绕过禁止自动获取或许可限制。

**授权状态独立记录：**`unknown / under_review / permitted / restricted / denied`；每个用途分别记录读取、自动获取、内部使用、公共图表、派生结果、下载分发、缓存/历史保留。即使 I1 完成，只要公共展示权未通过，就不能上线该数据。没有商业报价的源统一写“待报价”，不填 0 元。

## 4. 统一的优先级与接入队列

各专题中的 P0/P1 是专题内价值排序；跨专题排期以本表为准。优先级不意味着已授权或技术可用，也不等于建议同时实现所有 P0。

|批次/优先级|来源与范围|为什么优先|接下来具体做什么|关键通过条件|
|---|---|---|---|---|
|A0 / P0|统一来源注册、schema、覆盖矩阵|避免后续各源语义漂移|确定字段、状态枚举、发布门槛；登记已有代码证据|必填元数据完整；责任和授权状态可查询|
|A1 / P0|IMF BOP|可比国家层交易骨架|发现现行 dataflow/代码表，选少量不同地区系列测试|资产/负债符号明确；国家与期间缺口可见|
|A1 / P0|IMF PIP|双边证券持仓骨架|在已摄取 F51 基础上核验报告者、对手方、工具及保密规则|持仓不能冒充流量；汇总与残差可解释|
|A2 / P0|BIS LBS|跨境银行补充，不限股票|验证存量与官方调整后变化的系列和单位|集团内头寸与报告范围说明；禁止跨 BOP 求和|
|A2 / P0|美国 TIC、ECB SHSS|有实际证券交易和机构/工具细分|TIC 复核已有摄取；SHSS 先选公开样本，识别方法和格式断点|交易/存量分离；公开微观粒度不夸大|
|A3 / P1|加拿大、日 MOF/JPX、印度 NSDL/CDSL/NSE|扩展实际投资者交易观察|验证各源覆盖、买卖净额、成交/结算日、权限|每市场独立口径；不拼接为统一全球净流|
|A3 / P1|CFTC COT/TFF|官方期货头寸补充，采集范围可独立|查询报告种类、合约标识与修订样例|合约数/名义敞口/资金流严格分开|
|B1 / P1|ECB BOP/基金、Fed Z.1、BIS FX 调查|宏观与资产结构解释层|逐系列验证频率、季调年率和地理定义|不重复累计地区总量；调查不可标实时|
|B2 / P1|英国、土耳其、澳/新及其它国家官方统计|补地区覆盖|依覆盖矩阵缺口选择，不按接口数量堆积|当前发布路径、历史连续性、单位全部可追溯|
|B2 / P1|KRX、SET、IDX、HKEX、Saudi、DFM、NGX|地区交易所/投资者细分|优先官方文件或授权 feed，验证最新字段|不依赖未承诺的隐藏 API；明确国籍与居民差异|
|B3 / P1，许可先行|ICI、FINRA 聚合、DefiLlama|基金、债券活动、链上模块|核对用途许可，样本确认后决定是否实现|公开展示、派生图表、下载权分别明确|
|C1 / P2|EPFR、CLS、CME、TRACE 逐笔、Glassnode、Coin Metrics Pro、JPX 商业产品|填具体频率/覆盖缺口|写清所需字段与外部展示场景后申请报价|合同覆盖缓存、衍生结果与用户下载等实际用途|
|C2 / P2，受限|B3、TWSE 产品|高价值但不可默认采集/披露|B3 先授权；TWSE 先公共展示许可|未获得许可前不自动抓取或公开数据|
|C2 / P2，历史/候选|CVM、JSE、肯尼亚、科威特及股票目录候选国家|补历史和地域盲点|核查连续性、文件质量、正式接口和许可|未核验的来源维持 C/V1-H；不计入已覆盖|

先补齐 A0，对已有 PIP F51/TIC 连接器做证据与契约对齐，再完成一个 A1 来源到可追溯展示的闭环。第二个来源通过相同契约后，再扩展 A2/A3。每批结束更新覆盖矩阵与成本评估，避免一次启动几十个无法维护的爬虫。没有人力、采购与样本证据前，不给虚构的上线日期。

## 5. 最小数据契约与存储分层

下述为拟议契约，不声称已经符合当前仓库模型；实施前需与实际类型和数据库迁移方案对齐。

### 来源/数据集注册 `SourceDataset`

- `source_id`, `dataset_id`, `provider`, `official_url`, `documentation_url`, `access_method`（文档化 API / 官方文件 / 授权 feed / 手动样本）。
- `evidence_stage`, `evidence_url_or_artifact`, `verified_at`, `owner`, `next_action`, `blocker`。
- `rights_by_use`, `terms_url`, `license_evidence`, `license_expiry`, `attribution`, `cost_status`；未知值不可默认允许。
- `metric_type`, `metric_subtype`, `method_status`, `frequency`, `release_lag`, `release_calendar`, `history_start/end`；未知项显式为空并解释。
- `coverage_universe`, `exclusions`, `geography_basis`, `available_dimensions`, `classification_version`, `aggregation_rules`, `known_breaks`。

### 观测记录 `Observation`

- 主键至少含 `dataset_id + series_id + source dimensions + observation_period + vintage`，不能只用国家和日期；证券、份额和上市代码分开保存。
- 记录 `value`, `original_unit`, `unit_multiplier`, `currency`, `gross_net_basis`, `asset_liability_basis`, `sign_convention`。
- 地理字段分为 `reporter_geo`, `counterparty_geo`, `issuer_geo`, `listing_market` 等实际存在字段，并分别附 `geo_basis`；不支持的维度保持“不支持”，不是“未知国别”。
- 保留 `observation_start/end` 或 `as_of_date`, `publication_time`, `retrieved_at`, `last_checked_at`, `vintage/revision`, `source_observation_status`。
- `missing_reason` 区分未报告、保密、不适用、未分类；数值零是有效观察，不是缺失标记。
- `method_status`, `method_reference`, `quality_flags`, `raw_artifact_reference` 让原始值和派生值均可追溯。
- 如有币种转换或派生值，保留 `derived_from`, `formula_version`, `fx_source`, `fx_period_or_date`，不能覆盖原始记录。

### 展示能力 `ViewCapabilities`

显式声明是否支持时间序列、国家地图、对手方矩阵、行业、证券、投资者类别、双边交易、双边持仓。前端据能力开关视图，不从字段名称猜测；同一来源的不同系列也可能有不同能力。

### 分层及权限

1. **原始层：**在许可允许范围内保存文件/响应、请求参数、代码表、内容哈希及抓取记录；没有历史保留权时执行相应限制，不能一概永久归档。
2. **标准层：**只做明确、可重放的单位、符号和代码映射；原值不丢失；版本变更可回放。
3. **服务层：**按授权提供聚合缓存；公开图表权不自动给予原始下载权。密钥只能在服务端，不能写入前端或仓库。
4. **展示层：**附来源、覆盖、单位、期间、方法与更新时间。演示与正式数据隔离；失败时显示旧数据及失败状态，而不是换成演示数值。

## 6. 每源采集验证步骤

1. **读官方文档和条款：**确认数据产品与允许的访问方式。限制自动抓取的源先解决许可，不尝试镜像规避。
2. **发现当前系列：**获取 dataflow/代码表或文件目录；记录工具、部门、频率、币种、乘数和符号。版本不明不直接使用旧教程端点。
3. **小样本试验：**选择两个时期和不同报告主体，至少包括一个缺失/保密/修订场景；文件源核查脚注和跨页单位。样本响应、状态码和内容都留证，不只记录“成功”。
4. **验证覆盖：**先列明实际可得经济体—资产—指标—期间，再与计划覆盖宇宙对照；没有分母时只报告数量和缺口，不写百分比。
5. **质量核查：**与官方表核对样本；校验买减卖=净额、单位、符号、存量/期间、汇总残差、双重上市和地区汇总重复。误差容许范围依来源精度制定。
6. **实现适配器：**限流、超时、退避、幂等写入、断点续传、增量和定期修订回查。重试不能绕过授权失败；schema 变化应隔离数据并告警。
7. **记录调度：**依发布日历安排抓取与修订回查；月/季源不必每分钟访问。UI 每分钟检查缓存不意味着原始数据分钟级更新。
8. **发布审查：**确认展示与下载的权限，完成可访问性和失败状态测试后才启用数据集；记录版本和负责人。

## 7. 覆盖矩阵和验收 gates

覆盖矩阵每行使用 `dataset + geography basis + reporter/counterparty + asset + metric + frequency + period range + granularity`，并加 `evidence stage / rights / implementation evidence / freshness`。必须允许同一国家在不同资产、频率和指标下有不同状态。

|门槛|通过标准|未通过时行为|
|---|---|---|
|G0 范围|可说明数据真正代表谁、什么资产、哪个时期及哪些缺口|只作为候选，不计入覆盖|
|G1 获取|官方可用路径和样本可复现，错误/限流行为有记录|不宣称 API 可用，不承诺稳定采集|
|G2 语义|类型、单位、符号、时间、地理、分类全部明确|不聚合、不提供国家排名或流向推断|
|G3 质量|样本对官方值、聚合残差、修订/缺失测试通过|隔离异常，保留上次可靠版本|
|G4 权利|实际产品用途全部有可追溯授权或适用许可依据|禁用未经授权的展示/下载用途|

|G7 运维|发布周期、陈旧规则、告警负责人、重跑与回滚经过验证|不宣称生产稳定或实时|
